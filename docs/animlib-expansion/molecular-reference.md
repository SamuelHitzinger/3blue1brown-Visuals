## Existing repository capability and actual gaps

Inspected `shared/animlib/docs/molecules.md`, `src/molecule-types.ts`, `src/molecules.ts`, `src/molecular-data.ts`, `src/solid-types.ts`, and `docs/capabilities.md`; also prior DNA/protein style contract and full-film/smooth review documents under `docs/demos/dna-protein/`.

The earlier local film was based on a **different** reference: yourgenome, From DNA to protein – 3D (`gG7uCskUOrA`). Its own reviews say the near-exact target was not achieved and identify sparse cellular surroundings, cartoon-like domains, insufficient surface texture, and overly frontal/wide framing. I read those reviews; I did **not independently view that native film** in this pass. Existing capability is not a fidelity pass for the three new sources.

| Existing feature | Boundary relevant to these references |
| --- | --- |
| `s.molecule` / `createMoleculeBuilders` | Batches up to 10,000 supplied sites as octahedra or subdivided octahedra, uniform radius/material per call. It does not provide explicit chemical bonds, per-residue identity, or a connected backbone. |
| Host PDB importer | Legacy PDB, first model, residue or heavy-atom selection, stored chain/site labels; excludes HETATM. No mmCIF, assembly expansion, explicit bond graph, secondary-structure annotation, or missing-segment semantics. |
| `s.tube` | Useful generic polyline tube, but no sequence colors/IDs, chain-break contract, molecular representation correspondence, or residue-level annotation mapping. |
| Gaussian molecular envelope | Offline density approximation with smoothing and bounded mesh output; useful surface layer, but not a solvent-accessible surface or biochemical simulator. Smoothing can erase active clefts. |
| Morph/retained deformation | Mesh correspondence and deterministic time sampling exist. XYZ interpolation alone does not preserve covalent link lengths. Live connectors keep endpoints, not bond lengths. |
| Materials, contours, clip planes, labels | Existing ingredients should be reused. General atmosphere/depth of field, rich translucent interiors, and detailed organelles remain separate renderer/art tasks. |

The existing crambin asset (`1crn.json`) has 327 heavy atoms; its envelope has 1,042 vertices / 2,080 triangles. Existing `1jj2.json` has 6,567 selected sites across 30 chains; its envelope has 1,472 vertices / 2,940 triangles. 1JJ2 is a **large ribosomal subunit**, not a whole active translating ribosome. Arbitrarily swapping a chain for an unrelated envelope would break the representation identity required by the folding example.

Production constraints to retain: QuickJS compile budget 200 ms, source cap 256,000 characters, at most 20,000 vertices/triangles per mesh. Large prepared molecular data should come through the planned asset catalog rather than source-inline coordinate arrays.

## Smallest high-impact implementation boundary

**Priority 1: a self-contained molecular builder factory, usable by host and installed verbatim in QuickJS**, following `createMoleculeBuilders`. The implementer owns a new module, associated types/tests, and a focused proof. A separate integration pass wires the public scene API, compiler/runtime, exports, and docs to avoid conflicting edits.

1. **Explicit bonds and ordered backbone.** Input includes stable site/residue IDs, packed positions, per-site or per-segment colors, explicit edges, and chain breaks. Validate malformed indices, duplicate IDs, nonfinite coordinates, and zero-length edges. Never infer a bond across a missing residue or different chain merely because arrays are adjacent. Build bounded smooth mesh batches with deterministic output. Preserve a shared model origin and identifier-to-position mapping for annotations.
2. **Stable representation correspondence.** Sticks and residue beads consume the same IDs and coordinates; a surface endpoint is generated from those same source atoms. Crossfades retain location, scale, palette, and semantic labels. Reuse current envelope generation where suitable; do not implement another envelope algorithm in the first slice.
3. **Schematic fixed-link chain pose utility.** A deterministic joint-angle/forward-kinematics demonstration can preserve segment lengths while producing a compact chain. Explicitly label it a schematic conformational change, not a physical folding simulation or scientifically determined trajectory. Do not imply arbitrary endpoint XYZ interpolation has chemical validity. Backbone/bond builders are valuable even if this pose utility is a separate small module.

Protein ribbon/cartoon geometry with transported frames and explicit secondary-structure annotations is **Priority 2**, inferred from general scientific visualization needs. DNA paired ribbon backbones are directly observed in the transcription reference. Keep these concepts distinct. The first proof should prioritize the observed sticks/beads/surface progression and stable connected geometry over unobserved ribbon decoration.

Do not bundle mmCIF parsing, physical molecular dynamics, arbitrary volumetric lighting, full ribosomal mechanism simulation, or a new renderer into this first slice. Those are separate boundaries with their own evidence and budgets.

## Measurable acceptance for the first original proof

Render an original 6–10 second clip at native output resolution, 30 fps, with a single sequence-colored chain and a static/slow oblique camera. Inspect the exported clip in actual playback, every complete frame or a documented full native-frame review workflow, and explicit frames around every representation transition. A contact sheet alone cannot pass the motion gate. Independent reviewer compares to the listed source timestamps while retaining the scientific accuracy caveats.

- At every sampled evaluation time, all backbone links retain their intended lengths to relative error ≤ 1e-5; all coordinates/normals are finite. Tests include near-straight, sharp bend, chain break, duplicate-coordinate rejection, and repeated out-of-order time evaluation.
- Across representation changes, site IDs, sequence-color assignments, shared origin, and label targets remain identical. No links cross explicit chain breaks. The surface comes from the same structure and conformer as the stick/bead endpoint.
- Native frames show a readable continuous chain, smooth cylindrical bonds, stable depth ordering, and no popping, frame flips, detached labels, geometry cracks, or isolated beads mistaken for a connected backbone.
- Evaluate maximum declared input within production QuickJS and mesh limits. Report actual compile time, mesh counts, and failure behavior; do not infer runtime viability from host-only tests.
- Review reasoning/identity, readability, style comparison, and technical validity separately. Passing geometry tests cannot establish resemblance to PyMOL or Nucleus.

For a later Nucleus-style proof, require a close oblique view through a translucent active channel, paired/unpaired nucleotide identities, persistent template/transcript, local codon labels, and a mechanism-visible silhouette. Render-focused depth/lighting work should be judged separately from the backbone API.

## Reusable public sources and constraints

- [wwPDB usage policy](https://www.wwpdb.org/about/usage-policies): PDB archive data is CC0 1.0; preserve accession, source URL, model, selection, units, and scientific citation even where attribution is encouraged rather than legally required. The policy was read in this investigation.
- [RCSB 1CRN entry](https://www.rcsb.org/structure/1CRN): a small existing structure is suitable for a bounded representation proof. Reuse the repository's existing asset and provenance after verifying that all representations share the exact selected coordinates. Do not infer a folding trajectory from one deposited endpoint.
- [Mol* repository license](https://github.com/molstar/molstar/blob/master/LICENSE): MIT license was read. Its parsing/structure machinery is a candidate for host preprocessing; retain notices for reused code and pin/version the dependency. This is a candidate, not an added dependency or a claim that its renderer has been integrated.
- [Open-source PyMOL license file](https://github.com/schrodinger/pymol-open-source/blob/master/LICENSE): inspect the exact pinned license before any code reuse. The reference's attribution to PyMOL does not require adding PyMOL or copying its animation trajectory.
- Original procedural materials need no external bitmap textures for the first proof. If later acquiring models/textures, store per-asset source, license, author, modification history, and permitted redistribution alongside the catalog entry.
- Nucleus reference frames, surfaces, narration, and sound are not reusable production assets merely because the video is publicly viewable. The transcription repost's original ownership remains unresolved. Reference images are observation evidence only.
