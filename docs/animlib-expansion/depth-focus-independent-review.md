The shader displacement uses transformed camera-forward depth before perspective division; it does not use layer bias or object-center depth. The native rotated-camera matrix directly exercises that distinction. Sample color resolves to RGBA8, accumulates premultiplied in RGBA16F, and is composited once. Distinct per-sample GPU camera uniforms avoid the queued-write aliasing that would collapse all rays onto the last sample. Main HUD stays in its final sharp batch; regional screen geometry bypasses lens displacement while preserving group ordering. Scissors cover sample rendering and accumulation/composition. The resource pool is shared across samples/views and released on resize/disposal/backend replacement.

Fixed budgets are evaluated before GPU submission/upload/allocation for a rejected workload. Group depth passes and retained instances are included in the submitted-vertex estimate; nested groups are conservatively counted. RGBA16F capability failure is explicit/recoverable on WebGL2, while the zero-aperture path does not request it. The 44-byte-per-pixel focus pool accounting agrees with the four textures and their sample counts.

## Limits and API note

The independent scope did not rerun the entire native or portable suite. The author's reported 146/148 native result retains the two known exact-MSAA assertions, and the restricted portable 921/923 result retains two filesystem EPERM failures. They are not converted into passes by this review. No baseline assertion was weakened. Hardware throughput was not independently rebenchmarked: the documented 1.55/6.31/11.31 ms medians are author measurements of CPU render plus GPU queue completion, not GPU timestamp queries.

An exploratory probe found that authored `camera.animate({focus: undefined})` leaves the previous focus unchanged because the existing runtime JSON clone drops undefined properties. The supported way to turn focus off is the documented complete focus object with `aperture: 0`; partial camera changes intentionally preserve focus. The successful reviewer probe uses that supported contract. This is an API/documentation caveat, not evidence that a zero-aperture or omitted initial focus takes the optical rendering path.

Finite-sample lobes can become obvious at larger apertures or lower quality, transparent geometry retains existing ordering semantics, and the focused path is substantially more expensive. These limits are already stated in the feature documentation and remain applicable to downstream authored scenes.
