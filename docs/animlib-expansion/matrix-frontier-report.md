## Changes and reuse

- `src/diagrams/collections.ts` / `collection-types.ts`: optional ordinary custom
  content wrappers, vertical ordering, complete identity permutations through
  separated lanes. Same-displacement entries share a lane. Existing horizontal
  opposing-arc swaps remain. Sparse/invalid orders and overlapping schedules are
  rejected before scheduling mutation. Inputs retain the existing256-item bound.
- `demo/expansion/matrix-transport.js`: original columns `(1,-1)` and `(2,1)`
  remain beside their basis vectors. A copied first vector doubles, a copied
  second translates head-to-tail, columns copy into `2a1+a2`, then named row terms
  travel into arithmetic and produce `(4,-1)`. Existing native geometry, MathJax
  maps, anchors and timeline do all the work.
- `demo/expansion/frontier-reorder.js`: an accepted cost3 candidate enters beside
  costs5 and7, then all route/cost/destination groups sort coherently. Two C
  destinations have different candidate IDs. Cost7 remains on the stale record;
  graph distance changes directly7→3. Graph data and acceptance come from the
  existing Dijkstra trace. Purple/sans/ring style remains separate from matrix.
- `docs/identity-transport.md`: reusable authoring/API pattern and limits.

Audit correction: an earlier reference report listed `partColors` as existing.
It is not present in Geometry or the renderer; extra fields are ignored. These
proofs use separate colored handles instead. General per-part coloring remains
a distinct missing capability. No second formula engine was added.
