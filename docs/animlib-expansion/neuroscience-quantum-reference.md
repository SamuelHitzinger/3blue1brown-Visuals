### Measurable Artem-inspired proof

Author an original 6–8 second passage with three or five event rows. Derive rate curves from an explicitly stated deterministic kernel or supplied sampled data; do not invent a scientifically measured dataset. Preserve row colors, event timestamps, vertical ordering, and the shared horizontal domain. Reveal smooth curves over the event rows, then dim the ticks, then move the same traces aside while color-matched vector entries appear.

At a selected time, a shared cursor and markers must identify the same sample in every row; a corresponding state point must be calculated from those values. The sample point and its projected coordinates should agree to numerical tolerance before rendering. After a layout move the selected data coordinate must remain the same. A subsequent 3D trajectory can demonstrate the mapping, but should not be described as a recovered biological manifold without an actual model/data source.

Render acceptance: no endpoint snapping; no reversal of sample order; no joining across declared data gaps; no row-label swaps; all five colors remain stable. At 1280×720, selected points and local labels must remain readable, and the trace/vector correspondence must survive without narration. Inspect setup, progressive reveal, the interior of the layout movement, and a ≥0.7 second readable endpoint hold. These timing/size targets are proposed proof criteria, not measured universal artist rules.

## Existing engine versus concrete gaps

Inspected `shared/animlib/src/types.ts`, `core.ts`, `path.ts`, `runtime.ts`, `docs/reference.md`, `docs/capabilities.md`, and README. Existing capabilities already include vector text and named LaTeX parts, numeric `countTo`, SVG/smooth paths, explicit path correspondences, object/group transforms, attachments/connectors, camera transitions, clipped independent views, sampled surfaces, fixed-topology mesh deformation, scalar colors, outlines, section planes, and retained scene-time bindings. New helpers should compose these instead of replacing the renderer or adding a second scene engine.

| Need | Current boundary | Focused addition |
|---|---|---|
| Continuously calculated signal/trajectory | Retained bindings allow mesh `vertices`, but not path `points`. Author must rebuild or approximate with many morphs. | Add validated fixed-count `points` updates for point-authored paths, driven by `s.time` and controls. Preserve point order and open/closed semantics; reject writes to SVG `d` paths unless a separate explicit contract exists. |
| Progressive trace construction | ElementHandle exposes move/rotate/scale/fade/morph/count, but no native stroke-prefix reveal. | Add path stroke range/reveal with documented arc-length semantics. Preserve original complete geometry for later evaluation and seeking; implement before domain-specific wrappers. |
| Residual/guide marks | Existing connectors track endpoints, but no inspected public dash contract. | Add declarative stroke dash pattern and phase using a documented distance space. Keep dash clipping consistent with reveal, transforms and both GPU backends. Do not emulate every dash as an independent authored object. |
| Reliable data-to-world correspondence | Plots/axes are currently assembled manually from primitives. | A small pure coordinate-map utility plus sampled path helper should return mapping functions and ordinary handles. Explicit domain/range, invalid-sample policy, and shared mapping matter more than a large chart API. |
| Event rows / neural rasters | Can be authored from many separate short lines. | Initially a recipe or compound-path batching helper is sufficient. Benchmark several thousand ticks before proposing a separate primitive. Preserve row/event identities in authoring metadata. |
| Dense populations/scatter | Circles/spheres work; coordinate batching exists specifically for molecules. | Measure the real bottleneck first. If needed, generalize safe repeated-marker batching independently of molecule chemistry, with stable indices and shared picking/selection semantics. Not yet proven necessary by this small sample. |

Priority order: **points binding + reveal**, **dashes**, **small mapping/sampling helpers**, then benchmark-driven dense-data batching. Coordinate with the math/algorithm work, which independently found reveal and stable sample mapping needs. Avoid separate neuroscience, quantum, or regression engines.

## Integration checks that matter

1. The parent investigation found offline `render-video.mjs`/`render-frames.mjs` compile once and use ordinary `evaluateScene`, which can miss live time bindings. A time-dependent trace proof must use the same reactive sampling semantics as the production player; otherwise a static export could falsely appear to validate a live animation.
2. Changing a path’s geometry must invalidate relevant cached tessellation/bounds/overlap data without rebuilding unrelated retained geometry. Public limits should bound sample counts and reject NaN/Infinity rather than silently corrupting a frame.
3. Frame `t` must be a pure function of rest geometry, explicit parameters, and absolute time. Test forward/reverse/direct seeks, not only uninterrupted playback.
4. Adding line dashes/reveal affects geometry preparation, bounds, both GPU backends, hit testing if applicable, morphs, and export. A browser-only screenshot is insufficient integration evidence.
5. Scalar mesh fields and waves already exist through `surface`/`deform`/`scalarColors`; corrected channel scope does not justify claiming a missing quantum wavefield system. Any future complex-amplitude/phase encoding needs its own reference and mathematical contract.
