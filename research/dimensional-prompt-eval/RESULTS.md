# Dimensional prompt evaluation — findings

Work lives on `codex/dimensional-prompt-eval` in the managed `dimensional-prompt-eval/3yellow3white` worktree. The original `amilibsam` checkout and its pre-existing changes were preserved. The experiment baseline captures the user's dirty prompts at task start, not pristine `HEAD`.

## What the experiments establish

The nine-run first matrix correctly chose 2D for sine compression and genuine 3D for the saddle in every delivered result. It therefore establishes no routing advantage over the existing baseline. Explicit inference-based selection remains a clearer instruction than preferring 3D by subject category.

Complex structure is a separate failure. Both delivered first-matrix enzyme variants showed real cavities, depth and substrate approach, but represented the requested large folded protein as a smooth multi-lobed envelope with a surface trace. More guidance did not reliably produce the packed local structures visible in the supplied showcase. Native automatic approval missed this shortfall and some label/tangent readability defects. High reasoning was already enabled throughout; these results do not support blaming a low reasoning setting.

The second phase tests two narrower changes on the unchanged enzyme request: moving the exact construction checklist after the long API reference, and adding one real separate construction specialist to that same ordering. The specialist is host-orchestrated; the scene author does not have a nested-agent tool. Its proposal is advice, not compiled or rendered evidence.

## Experiment boundaries

Every trial starts from a new request and UUID and runs the production content pipeline: lesson drafting, editorial review and any revision, supported subtitle timing, scene authoring, validation and analytical inspection, native WebGPU review, and the normal bounded repair/re-review. No lesson, narration or scene source is seeded. Generated JavaScript is not manually edited.

All trials use `gpt-6-astra`, high reasoning, validated-reference output and host timing. Subtitle mode deliberately excludes paid speech. Optional Chromium author preview is consistently disabled; mandatory native review remains enabled. HTTP/storage orchestration and the separate thumbnail task are outside this content-generation comparison. Compiler limits, native gates and repair budgets stay unchanged. Effective prompts, hashes, source, images and usage are retained.

These are single trials per condition, not a success-rate study or proof of causality. Reasoning tokens are a subset of output tokens. Measured usage is not a dollar-cost estimate. An interrupted cold compile remains a failed delivery even if an unchanged source succeeds in a diagnostic warm or higher-budget compile.

## Final selection and checks

No experimental candidate is promoted. The task-start production baseline is retained because no candidate demonstrated a convincing overall visual improvement. Candidate A makes the requested 2D/depth decision rule explicit, but its trials did not establish a routing advantage and included a visible label collision plus one native delivery failure. Candidate B and the partial ordering/specialist trials still produced smooth envelopes with surface traces instead of the requested rich folded architecture. Shipping an extra specialist is not supported by the observed benefit.

The separate specialist did execute a real model call: 74.1 seconds, 16,663 input tokens and 1,950 output tokens (796 reasoning), before ordinary scene authoring. Its initial native review rejected the surrounding structure and a pocket-label endpoint. The ordering-only initial render also retained a broad smooth body with coil traces. Its sampled frames miss the deepest substrate seating hold, so that behavior is unverified. The specialist then failed native re-review after its bounded repair: the label endpoint was corrected, but the surrounding structure still read as a draped triangular bowl. Its complete failed run took 701.4 seconds and 12 provider calls, totaling 366,499 input and 21,781 output tokens (9,483 reasoning), with 235,904 cache-read tokens. Order-only was interrupted during repair, and its in-flight usage is unknown. Independent visual comparison assessed initial frames only; no final phase-two provenance audit ran after the stop instruction.

Verification already completed on this unchanged isolated production baseline: `npm run build` succeeded; 53 focused planning/editorial/scene-craft/authoring-reference/visual-gate tests passed. The separate research harness passed 26 focused tests and strict TypeScript checks before phase two. All nine phase-one provenance audits passed. No budgets, gates or generated sources were altered. No final encoded movie or interaction-playback certification is claimed.

The tested prompt alternatives, real helper prototype, reproducible harness, effective inputs, native evidence and failure reports remain on this branch for inspection. This research narrowed the failure to structural representation and review quality; it did not solve showcase-level complex 3D generation. The user requested immediate completion before further experiments or integration.
