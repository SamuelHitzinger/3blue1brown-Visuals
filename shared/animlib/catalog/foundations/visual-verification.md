# Visual verification and evidence limits

Keep four questions separate: is the represented reasoning correct, is it readable, does it follow the current visual direction, and is technical delivery valid? Compiler success or an encoded file answers only part of this.

Use the existing host validators, inspect_scene, preview_scene and independent visual review when supplied. Select reveal boundaries, motion interiors, closest approaches, settled holds and handoff/end state. Review real delivery dimensions and intended alternate aspect. Repair demonstrated defects while preserving approved narration, identities, controls, timing and earlier corrections.

The [coverage/evidence index](../../docs/expansion-index.md) maps existing proofs to exact reviewed scope; the [scene verifier](../../../../backend/prompts/scene-verify.md) states current production review criteria. Readiness in this catalog does not supersede those records.

Confirm reverse seeks and paused interactions when relevant. A contact sheet cannot establish continuous motion, full-path occlusion freedom or acoustic alignment. Do not claim to have seen unavailable frames. Missing scientific data, unsupported preparation or failed rendering must remain explicit limitations, never an invented approval.

When adapting a proof, produce a new source/artifact identity and preserve frozen reviewed media. Passing reuse tests does not prove equal visual quality for all future generated lessons, and asset reuse alone is not a measured speed improvement.
