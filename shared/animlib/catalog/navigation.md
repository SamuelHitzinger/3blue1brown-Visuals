# Visualization catalog navigation

Use `search_visualization_catalog` to find resources (exact assets/data sources), techniques (reusable domain representations), and foundations (general explanatory skills). Search for the storyboard's relationship, mechanism, invariants, and required data; optional domain and readiness filters narrow the results. `intent` adds curated teaching relationships; `capabilities` requires exact all-of API names. Synonyms and common plurals are indexed; if no result fits, try a different relationship rather than repeating a long topic sentence. Read relevant entries with `read_visualization_catalog` before choosing an unfamiliar approach. Follow only related IDs needed by this scene. Search returns compact metadata within a byte budget; use nextOffset for the next page, not offset + requested limit.

Start from the teaching need, then choose a suitable technique, exact resources, and applicable foundations. Reuse the method while preserving the approved example, identity, narration, timing, and reveal order. If nothing fits, use the installed API and current quality guidance; do not force the story into an unrelated template.

For an unfamiliar API example, use `read_animlib_reference` when supplied. Its small index lists stable section IDs; read the selected recipe and follow nextOffset for a long section. Catalog Markdown links and host file paths are navigation hints, not files automatically readable inside scene code. The general scene API and quality contract still apply. Reusable scientific helpers can compute modal states, conservative transfers, complex interference and event-rate samples; select them only when their stated assumptions match the concept. Construct and cache bounded state once, then bind geometry and readouts to the same absolute-time result. Runnable recipes are construction seeds, not preapproved complete explanations.

Readiness describes availability, not scientific or visual approval. A catalog asset is not loaded merely because it is listed. When supplied, `resolve_visualization_resource` selects real model/code/data references, checks exact capabilities and reports missing inputs or unsupported routes. Model publication needs an exact selection and `prepare:true`; use its returned model ID. Read code via `read_animlib_reference` and selected JSON via `read_visualization_resource` with its hash and pagination. `publish_model` remains available for other supported model sources. External data references and animated GLB are not automatically prepared. Preserve source provenance, distinctions between measured/calculated/schematic data, and the entry's limits. Catalog IDs are authoring references, never citations to supplied lecture/source material. Validation and visual review remain authoritative. Reviewers may consult the catalog without receiving preparation tools.

Before reusing molecular resources, read the full reuseContract: applicable and excluded claims, required inputs, preparation route, motion limitations and fallback composition. Match exact identity and representation; prepare the required input when reuse does not fit. Rigid subunit motion preserves internal distances; authored keyframes are illustrative, never inferred molecular dynamics.
