# Visualization catalog

This catalog lives with animlib and describes reusable authoring knowledge. It is separate from the renderer's asset descriptor catalog.

- **Resources** are exact assets, data and sources, with provenance and preparation requirements.
- **Techniques** are reusable domain explanations selected by the storyboard's relationship, identities and invariants.
- **Foundations** are general quality and explanatory skills used across techniques.

Start with the teaching need. The compact [navigation guide](navigation.md) is injected directly into planning, authoring, review, repair, and lecture synthesis. Search the versioned [index](index.json), read selected records, and follow their related IDs only as needed. The production host exposes bounded ID-only search/read tools; listing a source does not fetch it, register an asset, or authorize a scientific or visual claim.

A ready record describes an available method or supported publication route. Host-preparation records require the stated host capability and input selection. Reference records supply background without promising executable support.

To add a record: choose a stable lowercase ID, concise discovery metadata, one bounded document under its tier directory, related IDs and explicit limits. Use optional aliases for real disciplinary synonyms and capabilities for exact scene API names or explicitly named external preparation. Record exact inputs, units, preparation, provenance, representation meaning and verification. Separate analytic calculations, supplied measurements, deposited coordinates and schematic motion. Link primary scientific sources and record their review date; reference-only data sources do not imply an installed downloader or parser. Preserve historical assets and proof identities. Do not include lesson-private source material. The host validates index shape, entry paths, relationships and response budgets; catalog tests also verify linked local resources. Keep the general prompt constant as the catalog grows.

The root index is a small versioned routing manifest. Metadata lives in independently bounded tier/domain shards under `indexes/`; split a growing domain into another shard and add its path to the root. Documents stay separate and are read only by selected ID. The host builds normalized token postings, stable ID lookup and tier/domain/readiness indexes once. Search ranks covered query terms before exact ID/title/alias matches, with stable ID ties; it does not use fuzzy substring matching. Common English plurals and hyphen-separated terms are normalized. Keep aliases explicit rather than relying on undocumented semantic inference.

HTTP search retains complete public records and supports domain/readiness filters. Model tools return compact discovery summaries, at most 20 per call and 12,000 UTF-8 JSON bytes; `nextOffset` reflects the number actually returned. A selected model detail retains its complete document/provenance/limits and up to six compact related summaries under 28,000 bytes. Related summaries are dropped first if necessary; an oversized detail raises an error instead of silently truncating a limitation or recipe. Each catalog document read remains at most 16 KB. Related traversal is cycle-safe and bounded. Adding records does not enlarge every agent prompt.

The interdisciplinary techniques cover fields, waves, mechanics, dynamical systems, signals, optics, circuits, elasticity, probability, reactions, ecology, orbital motion, terrain and neuroscience. Four [executable construction seeds](recipes/README.md) use [bounded scientific state](../docs/scientific-state.md); ready means supported construction under stated assumptions, not independently approved visual output. Dense data, numerical solvers and external source ingestion remain separately prepared inputs.

Current host safety ceilings are 128 shards of 256 KB each (at most 2,000 entries per shard). These are defensive I/O/memory limits, not a target library size. At larger scale, measure posting-index build time, resident memory, selective and broad retrieval separately. `bun backend/scripts/benchmark-catalog.ts` compares current lookup with the previous scan over 10,000 synthetic records; it is a retrieval benchmark, not a claim about model generation latency. Reload deployment after catalog changes so cached metadata matches its versioned documents.

Molecular reuseContract fields are bounded metadata; full contracts accompany selected detail and are excluded from model discovery summaries. Documents use a process LRU capped at 128 entries / 1 MiB, with containment and nanosecond stat signature checks on every read so development Markdown edits are visible. Immutable strings and defensive metadata copies prevent caller mutation. Index metadata remains versioned for the process: restart after editing shards or routing metadata. Full geometry remains in prepared artifacts outside the catalog.
